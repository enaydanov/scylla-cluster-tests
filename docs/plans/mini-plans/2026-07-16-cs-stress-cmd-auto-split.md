# Mini-Plan: Auto-split single stress commands across loaders (`!auto_split` YAML tag)

**Date:** 2026-07-16
**Estimated LOC:** ~750
**Related PR:** none yet

## Problem
Test-case YAMLs like `test-cases/performance/perf-regression-predefined-throughput-steps.yaml` manually pre-split 6 stress-command fields (`prepare_write_cmd`, `stress_cmd_w`, `stress_cmd_r`, `stress_cmd_m`, `stress_cmd_cache_warmup`, `stress_cmd_read_disk`) into N nearly-identical strings, each with a hand-computed `n=`/`-pop seq=X..Y` slice, where N must equal `n_loaders`. This is repetitive, error-prone (one file in the repo has 4 pre-split pieces with `n_loaders: 1`, an already-detected drift), and must be redone by hand whenever `n_loaders` changes.

## Approach
This went through several design iterations before landing on the final approach:

1. **First iteration** (superseded): a separate `cs_stress_cmd_auto_split: bool | list[str]` config parameter. Worked, but decided against - required a whole extra option to keep in sync with the fields it targeted, and the `true`/list duality was extra ceremony.
2. **Second iteration** (superseded): a `!auto_split` YAML tag written directly on the value it targets, with the tag stripped from the *raw* dict returned by `anyconfig.load()` before merging into `SCTConfiguration`, and the tagged field names tracked in a `PrivateAttr` (`set[str]`) consumed once at the end of `verify_configuration()`. This worked, but had two real issues: (a) the production entry point `init_and_verify_sct_config()` calls `log_config()` *before* `verify_configuration()`, so the split wasn't reflected in the logged config for real test runs; (b) the tracked-set accumulation was strictly additive across every merged source, so a field tagged in an earlier-merged file but overridden with a plain, untagged value in a later-merged file (or env var) incorrectly stayed marked "tagged" forever - silently violating the opt-in design.
3. **Third iteration**: model the tag as a proper Pydantic type (a `BaseModel`, not a `str` subclass) instead of a side-channel extracted from raw dicts, apply the split inside `SCTConfiguration.__init__()` itself (not `verify_configuration()`), and use a small curated field-level type (`SplittableStringOrList`) to scope which fields support the tag. Implemented in a standalone `sdcm/utils/cs_stress_cmd_split.py` module.
4. **Final approach** (this PR): everything merged directly into `sdcm/sct_config.py` - no separate module. The split-computation logic became a method on the tag class itself rather than a free function, and the apply step reuses the pre-existing `stress_cmd_params` field-name list (already used elsewhere in `SCTConfiguration` for other stress-command-related checks) instead of a bespoke type-driven scan. See implementation facts below for the final, current shape.

Key implementation facts, verified empirically along the way:
- `Splittable` (in `sdcm/sct_config.py`) is a `pydantic.BaseModel` (a single `value: str` field), **not** a `str` subclass. This is deliberate: a `str` subclass would satisfy `isinstance(value, str)` and pass silently through any plain `StringOrList` (`list[str]`) field, coercing to a plain string with zero indication the tag was ignored (verified empirically). A `BaseModel` is structurally incompatible with `str`/`list[str]`, so any field that hasn't opted into `SplittableStringOrList` automatically raises a `pydantic.ValidationError` when tagged - no manual "which fields were tagged" bookkeeping needed at all, and no risk of a silently-ignored tag on the wrong field.
- `Splittable` validates its own content at construction time via `@model_validator(mode="after")`: `"cassandra-stress" in value` (matching `sdcm/tester.py`'s own `run_stress_thread` dispatch check, not `.startswith()`, since the command may be prefixed with JVM options or be a `cql-stress-cassandra-stress` variant) and that it has a splittable `-pop seq=X..Y` range. Both checks fire immediately at YAML-parse time, before the value is even associated with a field name.
- `Splittable.split_stress_cmd(num_parts)` is a **method** (not a free function taking a raw string): it divides the top-level `n=` (if present) and `-pop seq=X..Y` independently and proportionally across `num_parts` (via a static helper `_split_evenly`), last chunk absorbing any remainder, and returns `[self.value]` unchanged when `num_parts` isn't worth splitting further. Verified by hand to reproduce all 6 real examples in the target YAML exactly.
- `SplittableStringOrList = Annotated[Splittable | list[str], BeforeValidator(str_or_list_or_eval_splittable), InputType("str | list[str]"), Field(json_schema_extra={"appendable": True})]` is applied only to a small curated set of fields: `stress_cmd`, `stress_cmd_w`, `stress_cmd_r`, `stress_cmd_m`, `stress_cmd_read_disk`, `stress_cmd_cache_warmup`, `prepare_write_cmd`, `prepare_stress_cmd`. The union is at the **field** level (`Splittable | list[str]`), not the list-item level (`list[Splittable | str]`) - verified this matters: the tag represents the field's entire raw value (a single command, before list-normalization), not one element of an already-listified value. All other `StringOrList` fields are completely untouched.
- **Caught via `git status` while implementing**, not by design upfront: `configurations/performance/cassandra_stress_gradual_load_steps_i8g_mini_many_connections.yaml` (already committed on this branch, from earlier work) uses `!auto_split` on all 6 of the originally-motivating fields, including `stress_cmd_read_disk` and `stress_cmd_cache_warmup` - both initially left out of the curated list. Verified end-to-end against this real file after adding them (all 6 fields correctly split into 8 pieces, matching its `n_loaders: 8`).
- `str_or_list_or_eval_splittable()` is a **dedicated** wrapper, not a modification of the shared `str_or_list_or_eval()`: it short-circuits for `Splittable` (returned as-is) and otherwise delegates entirely to the existing, unmodified `str_or_list_or_eval()`. This keeps the change fully contained to the opted-in fields with zero blast radius on the other ~40 `StringOrList` fields.
- Verified empirically end-to-end (construction, `validate_assignment=True` reassignment, `copy.deepcopy`, and the real `anyconfig.merge()` → `self[key] = val` merge path used by `merge_dicts_append_strings`) that: a tagged value survives intact through the whole merge pipeline; a later-merged source overriding the field with a plain, untagged value automatically and correctly reverts it to plain `list[str]` (no bookkeeping needed - this is just normal Pydantic validated assignment); and a field typed `list[str]` (not opted in) raises `ValidationError` immediately.
- SCT loads all config files via `anyconfig.load(paths)` (`sdcm/sct_config.py`, `SCTConfiguration.__init__`), which forwards an optional `Loader=` kwarg straight through to the underlying PyYAML backend. The tag is registered on a **dedicated** `SctYamlLoader(yaml.SafeLoader)` subclass (also now defined directly in `sct_config.py`), never the global `yaml.SafeLoader` - registering on the global class would silently make `!auto_split` "work" (and reject unrelated files without it) across ~40 unrelated `yaml.safe_load()` call sites elsewhere in the codebase.
- `_apply_cs_stress_cmd_auto_split()` is called once, at the very end of `SCTConfiguration.__init__()` (after the env-var merge) - not from `verify_configuration()`. It iterates `self.stress_cmd_params` - a pre-existing field-name list already used elsewhere in `SCTConfiguration` for other stress-command-related checks (e.g. c-s profile file existence, stress-tool detection for loader prep) - checking `isinstance(self.get(name), Splittable)` for each, and always resolves the tag away (via `tag.split_stress_cmd(num_loaders)`, which itself returns `[tag.value]` unchanged when nothing needs distributing) by the time it returns - no `Splittable` instance ever survives past construction. Reusing this existing list (a superset of the actually-`SplittableStringOrList`-typed fields) is safe: only fields typed `SplittableStringOrList` can ever hold a `Splittable` value in the first place, regardless of which names are scanned.
- A split list is only correctly pinned 1-command-per-loader when `round_robin=True` (confirmed via `DockerBasedStressThread.configure_executer`, `sdcm/stress/base.py:81-92` - otherwise each piece runs on **every** loader). `_apply_cs_stress_cmd_auto_split()` raises if a split produced >1 piece and `round_robin` isn't set; no requirement when `n_loaders == 1` (a no-op).
- `sdcm/utils/lint/docs_linter.py` bypasses `SCTConfiguration`/`anyconfig` entirely and parses test-case YAML directly - it has **two** independent parse call sites (`lint_test_metadata()` and `cross_reference_config()`, the latter re-reading the same file separately). Rather than importing `Splittable`/`SctYamlLoader` from `sct_config.py` (which would couple a lint tool to the full config module), it defines its own tiny, self-contained `StripAutoSplitLoader(yaml.SafeLoader)` that strips the tag directly to a plain `str` at parse time - no separate unwrap step needed, since the loader itself never produces a wrapper object.
- Do **not** touch the existing `perf-regression-predefined-throughput-steps.yaml` in this PR - converting it to the new syntax is a natural, low-risk follow-up once this lands, kept separate to stay reviewable.

## Files to Modify
- `sdcm/sct_config.py` - all `!auto_split` machinery lives here (no separate module):
  - `Splittable(BaseModel)`: `value: str` field, `@model_validator(mode="after")` combining both content checks, `_split_evenly()` static method, `split_stress_cmd(num_parts)` method.
  - `str_or_list_or_eval_splittable()` and `SplittableStringOrList` (next to `StringOrList`). `str_or_list_or_eval()` itself is unmodified.
  - `SctYamlLoader(yaml.SafeLoader)` with `construct_auto_split()` registered for `!auto_split`.
  - Field annotations changed from `StringOrList` to `SplittableStringOrList` for: `stress_cmd`, `stress_cmd_w`, `stress_cmd_r`, `stress_cmd_m`, `stress_cmd_read_disk`, `stress_cmd_cache_warmup`, `prepare_write_cmd`, `prepare_stress_cmd`.
  - `_apply_cs_stress_cmd_auto_split()`: iterates `self.stress_cmd_params`, checks `isinstance(self.get(name), Splittable)`, calls `tag.split_stress_cmd(num_loaders)` and writes the result back; raises if a split produced >1 piece without `round_robin`. Called once at the end of `__init__()`.
- `sdcm/utils/lint/docs_linter.py` - both YAML-parsing call sites (`lint_test_metadata()`, `cross_reference_config()`) use the local `StripAutoSplitLoader`.
- `unit_tests/unit/test_cs_stress_cmd_split.py` - golden split tests and edge cases now call `Splittable(value=cmd).split_stress_cmd(n)` directly (no free function/helper); the two "no splittable range" error tests now expect the raise at `Splittable(...)` construction time; a construction-based parametrized test replaces the old standalone `is_single_splittable_command()` check.
- `unit_tests/unit/test_cs_stress_cmd_auto_split_config.py` - exercises `SCTConfiguration` end-to-end through the public API only, unaffected by the internal reorganization: assertions happen directly after `SCTConfiguration()` construction; the two exception-expecting tests expect the raise at construction time; covers tagged-then-overridden-untagged (via a later config file, and via an env var) correctly not splitting, and tagging a non-curated `StringOrList` field raising `pydantic.ValidationError` automatically.
- `unit_tests/unit/test_test_docs_linter.py` - non-crash tests for both `lint_test_metadata()` and `cross_reference_config()` kept, docstrings updated to no longer reference the removed module.
